## In brief

The regular funded phase of IncluLearn.AI began on **1 October 2026**. Since 2 October, the project's own public portal at **https://inclulearn.owli-ai.com/** has also completed its technical acceptance and is available.

The portal is intended to provide an understandable entry point to the project goals, current developments and future opportunities to participate. At the same time, IncluLearn.AI deliberately separates three things that can easily be confused: **public project information, the synthetic demo and future pilot operation**.

## A public entry point for the project, advisory board and professional community

The new portal brings together the most important public entry points under a dedicated project address. These include in particular:

- an understandable project overview,
- public news and developments,
- information about planned pilot access.

This means that people do not need to know the internal GitHub repositories in order to understand what the project is working on and which next steps are planned.

## Demo is not the same as pilot

The existing test demo at **https://inclulearn-test.owli-ai.com/** deliberately remains a separate path.

Using synthetic data, it demonstrates how workflows, review, material preparation and individual functions might work. This does not imply approval for real user data or production operation.

For later real-world pilot use, a **separate private application path** is planned. It will only be opened once the necessary technical, organisational, data-protection and approval gates have been satisfied.

## Why this separation matters

In a research and transfer project, a public demo, a production platform and pilot operation can easily be perceived as the same thing.

IncluLearn.AI therefore deliberately separates:

**Portal → public information**

**Demo → synthetic, publicly visible test path**

**Pilot app → future protected access for real-world evaluation**

This separation is intended to keep expectations clear and prevent a publicly reachable prototype from being mistaken for a production-ready application.

## What the project start means

The project start is primarily an organisational and technical transition – not a scientific result in itself.

The work documented in September remains **preparation**. New work from 1 October onward is classified as regular funded project work when it actually takes place in that period.

For the Newsroom, this distinction is important: preparation, ongoing project work and later research results should remain clearly separated in time and substance.

## Where partner feedback is particularly useful now

The public portal also creates a shared reference point for the advisory board, practice partners and external interested parties.

Feedback is particularly useful on:

- whether the project goals are understandable without a technical background,
- which information about the pilot and collaboration is still missing,
- which content should be easier for practice partners to find,
- and which questions should be answered publicly before real pilot access is opened.
