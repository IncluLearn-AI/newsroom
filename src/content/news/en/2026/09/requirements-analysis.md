## From a project idea to traceable requirements

A dedicated working base was prepared for needs and requirements analysis. It connects target groups, needs, typical workflows, use cases, functional and non-functional requirements, and accessibility and didactic aspects.

The central traceability chain is:

**Source/evidence → actor/target group → need → use case → requirement → acceptance criterion → implementation → evaluation**

This is intended to make it possible to trace why a feature exists and which evidence it is based on.

## Hypotheses are not yet validated requirements

The currently documented needs and requirements are mostly drafts or hypotheses. This status is explicit. They are intended to be validated through interviews, workshops, user tests or other robust evidence.

Preparation included research on media conversion centres, interview and analysis templates, safe storage boundaries, and legal and security-related requirement fields.

## Early formative BVI user tests

Toward the end of this preparation phase, a template for early formative testing with blind and visually impaired users was integrated into the traceability structure. Subject approval, sharing and technical release are deliberately treated as separate steps.

## Context

The structure does not yet create validated user requirements. It creates the basis for deriving, checking and later tracing such requirements against implementation and evaluation during the project.
